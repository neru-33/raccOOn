# 리포트 작성

`report.json`이 기록이고 `report.md`는 사람이 읽는 요약이다. `report.md`는 두 부분으로 이루어진다.

| 부분 | 작성 | 내용 |
| --- | --- | --- |
| 요약 | 코드 | 실행·매핑·리뷰 상태, 기능·품질·합계 점수, 항목별 결과, 오류와 로그 발췌 |
| 해설 | 모델(선택) | 총평, 점수 근거, 확인 질문과 응답 수준 |

점수와 판정은 요약 표와 `report.json`이 기준이다. 해설은 같은 `report.json`을 입력으로 받아 해석만 하며, 점수를 바꾸거나 다시 계산하지 않는다.

## 요약

- `task.json`을 함께 받으면 규칙의 `description`과 루브릭의 `title`로 항목 이름을 표시한다. ID는 괄호 안에 함께 남긴다. 없으면 ID만 표시한다.
- 채점하지 못한 값(`null`)은 `보류`로 표시한다.
- 표의 `|`와 줄바꿈은 이스케이프하고, 로그 발췌는 내용에 포함된 백틱보다 긴 코드 펜스로 감싼다.

## 해설

`--review live`이고 채점이 끝난(`run_status: graded`) 실행에서만 만든다. 평가에 쓰는 모델 연결(`EVALUATOR_*`)을 그대로 쓰며 도구와 응답 스키마는 쓰지 않는다. 모델에는 `task.json`의 `task_summary`, `rules`, `quality_rubric`, `review_instructions`와 `report.json`을 준다.

정해 둔 형식은 다음 세 제목뿐이고, 제목 안의 내용은 모델이 정한다.

| 제목 | 요청 내용 |
| --- | --- |
| `## 총평` | 잘한 점과 부족한 점 |
| `## 점수 근거` | 감점·보류 사유. 코드 위치와 관측값을 인용하고 확인된 사실, 가설, 근거 부족을 구분 |
| `## 확인 질문과 응답 수준` | 응시자에게 되물을 질문 3~6개와 질문마다 목적, 약한·적절한·강한 응답의 모습. 리포트의 내용에 근거해야 함 |

리포트에 담긴 제출물 유래 텍스트(리뷰 사유, 로그 발췌)는 데이터로만 다루도록 지시한다. 모델 호출이 실패하거나 빈 응답이면 요약은 그대로 쓰고 해설 자리에 실패 사실을 남긴다. 요청 오류가 아닌 예외의 내용은 남기지 않는다. 해설은 `report.json`의 `errors`나 종료 코드에 영향을 주지 않는다.

해설 언어는 한국어로 고정되어 있다. 질문과 응답 수준은 모델의 판단이므로 출제자가 검토한 뒤 쓴다.
