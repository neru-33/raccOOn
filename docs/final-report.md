# raccOOn 최종 결과보고서

## 1. 프로젝트 개요

raccOOn은 과제 설정과 제출물을 받아 프로그램의 실제 동작을 검사하고, 기능 점수와 품질 판단의 근거를 리포트로 남기는 CLI 평가 엔진입니다. 제출물마다 API 경로와 요청 형식이 달라도 같은 과제 설정과 배점 규칙을 적용할 수 있습니다.

최종 구현은 API 사용법 탐색, 제출물 실행, 기능 채점, AI 품질 리뷰와 근거 확인, 리포트 생성을 한 명령으로 연결합니다.

## 2. 구현 결과

| 단계 | 구현 내용 |
| --- | --- |
| 실행 준비 | CLI가 과제 설정과 제출 경로를 확인하고 제출물을 실행용 복사본으로 준비합니다. 대화형 터미널에 현재 단계, 매핑 시도, 검사 회차와 소요 시간을 표시합니다. |
| API 매핑 | 평가 에이전트가 제출 문서·소스와 앱에서 제공하는 API 명세를 참고해 호출 방법을 찾습니다. 실행기가 시험 요청으로 매핑을 확인합니다. |
| 기능 검사와 채점 | 실행기가 과제에 정해진 검사를 실행하고 회차별 관측값을 기록합니다. 채점 코어가 필수 기록을 확인하고 과제의 배점 규칙을 적용합니다. |
| 품질 평가 | 별도의 AI 세션이 코드·문서와 검사 기록을 읽고 항목별 판단과 근거 위치를 제안합니다. 코어는 인용한 파일·줄과 관측값 참조를 확인하고 배점표에 따라 점수를 계산합니다. |
| 결과 전달 | 점수, 감점·보류 근거, 실행 상태를 JSON과 Markdown으로 저장합니다. 모델 해설을 사용하는 실행에서는 총평, 점수 근거, 확인 질문을 Markdown에 덧붙입니다. |

API 탐색과 품질 리뷰는 대화 기록과 도구 권한을 따로 관리합니다. 실행 중 오류가 나거나 필수 관측값이 빠지면 기능 점수를 보류합니다. 품질 판단에 필요한 근거를 찾을 수 없으면 해당 항목과 품질 총점을 보류합니다. 기능 점수와 품질 점수가 모두 산출되면 두 값을 더해 총점을 계산합니다.

핵심 기술은 **Python**과 **Rich** 기반 CLI, **OpenAI 호환 API**를 통한 모델 연동, **Docker Compose** 기반 제출물 실행입니다. 예약 과제 실행기는 **PostgreSQL**과 **Grafana k6**를 사용합니다. 과제 설정과 실행 산출물은 **JSON Schema**로 검증합니다.

## 3. 예약 과제와 예제 결과

[선착순 좌석 예약 문제지](../examples/reservation/problem.md)의 핵심 조건은 마지막 한 자리에 요청이 몰려도 한 명만 확정하는 것입니다. 실행기는 정원 1명인 행사에 서로 다른 사용자 요청 50건을 동시에 보내는 검사를 세 번 수행합니다. 확정 응답 수를 세고, 행사 조회 API가 반환한 남은 자리로 확정 예약 건수를 계산합니다.

| 평가 영역 | 배점과 기준 |
| --- | --- |
| 기능 40점 | 예약 생성·조회 각 8점, 동시 요청 검사 회차당 최대 8점입니다. 한 회차라도 확정 응답이 2건 이상이면 동시 요청 항목은 0점입니다. |
| 품질 60점 | 아키텍처 15점, 코드 품질 20점, 문서 품질 15점, 추가 기능 10점입니다. 각 항목의 판단 수준과 배점은 과제 설정에서 정합니다. |

세 예제의 API 경로와 동시 요청 처리 방식이 다릅니다. 아래는 [예제 문서에 기록된 검사 결과](../examples/reservation/README.md#예시-제출물)입니다.

| 제출물 | 예약 처리 방식 | 기록된 동시 요청 검사 결과 |
| --- | --- | --- |
| `basic` | PostgreSQL에서 행사 행을 잠근 상태로 정원을 확인하고 예약을 저장 | 세 회차 모두 1건 확정 |
| `local-lock` | 각 실행 프로세스 내부에서 요청을 순서대로 처리 | 여러 프로세스에 요청이 나뉘면서 회차별 2~4건 확정 |
| `robust` | PostgreSQL에서 행사 ID별로 잠그고, 사용자 중복 예약과 동일 키 재전송의 이중 처리를 방지 | 세 회차 모두 1건 확정 |

## 4. 검증

보고서 작성 시 구현 커밋 `9fdfd46`에서 `python -m pytest -q -rs`를 실행했습니다. **258개가 통과했고 15개가 건너뛰어졌습니다.** API 매핑 재시도, 규칙 채점, 리뷰 오류 처리, CLI 진행 표시, 리포트 출력을 자동 테스트로 확인했습니다. Docker 통합 테스트 14개와 심볼릭 링크 권한이 필요한 테스트 1개는 이번 실행에서 건너뛰었습니다. 작성 환경에서는 Docker 데몬에 접근할 수 없어 3절의 동시 요청 결과는 저장소에 기록된 결과를 인용했습니다.

## 5. 실행과 결과 확인

저장소 루트에서 Python 3.11 이상과 Linux 컨테이너를 실행할 수 있는 Docker Compose v2를 준비합니다. `.env.example`을 참고해 로컬 `.env`에 `EVALUATOR_API_KEY`와 `EVALUATOR_MODEL`을 설정합니다. 별도의 OpenAI 호환 엔드포인트를 사용하면 `EVALUATOR_BASE_URL`도 지정합니다.

```powershell
python -m pip install -e ".[model,dev]"
python -m evaluator run --task examples/reservation/task.json --submission examples/reservation/submissions/robust --out runs/demo-robust --review live
```

다른 예제를 실행하려면 `--submission`을 해당 폴더로 변경하고 `--out`에는 새 경로를 지정합니다. 예약 예제에서 `--review off`를 사용하면 기능 점수만 채점하며, API 탐색에는 모델 연결이 필요합니다.

| 결과 파일 | 확인할 내용 |
| --- | --- |
| `report.md`, `report.json` | 읽기용 요약과 구조화된 점수·근거·보류 사유 |
| `mapping.json` | 시험 이력과 확인한 API 호출법 |
| `observations.json` | 검사 회차별 관측값과 실행 도구 정보 |
| `ai_review.json` | 유효한 품질 리뷰의 항목별 판단, 근거 참조, 원인 가설 |

## 6. 적용 범위

현재 프로토타입은 로컬 CLI와 등록된 실행기로 구동합니다. 새 과제는 `task.json`과 실행기 설정으로 추가할 수 있으며, 다른 실행 환경이 필요하면 해당 환경을 지원하는 실행기를 연결합니다.
